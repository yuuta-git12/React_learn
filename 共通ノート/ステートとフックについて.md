# ステート
- コンポーネントで値を保管し、表示を更新するのに不可欠
- コンポーネント内でデータを保持し、管理するためのオブジェクト
- 必要に応じて幾つでもステートを作成することができる
- 関数が実行し終えた後でも、ステートの値は保たれる
- ステートの保管場所　→ Reactグローバル環境
  - React全体を管理するグローバルな環境
  - **ステートフック**を使うことで、ステートの値をグローバル環境に保管したり、取り出したりできる
- 作成されたステートは、ページをリロードすると初期値にリセットされる（ブラウザのメモリ上に保持されるため）
- ステートの値が変更されると、その**コンポーネントは自動的に再レンダリング**される
- **注意**: ステートを直接変更してはいけない（例: `state = newValue` はNG）。必ず更新関数を使う

# フック
- コンポーネントを拡張する技術
- **コンポーネントに再利用可能な振る舞いを付加するために用意されたもの**
- フック名は必ず`use`で始まる（useState, useEffect, useRefなど）

## フックのルール（重要）
1. **トップレベルでのみ呼び出す** - ループ、条件分岐、ネストした関数内では呼び出さない
2. **関数コンポーネントまたはカスタムフック内でのみ使用** - 通常のJavaScript関数では使用できない

```tsx
// 正しい使い方
function MyComponent() {
  const [count, setCount] = useState(0);  // OK: トップレベル
  return <div>{count}</div>;
}

// 間違った使い方
function MyComponent() {
  if (condition) {
    const [count, setCount] = useState(0);  // NG: 条件分岐内
  }
}
```

## ステートフック (useState)
- ステートを利用するために用意されているフック
- `useState`関数で用意されている　→ ステートを作成するためのもの
- useStateの初期設定
```tsx
const [変数A, 変数B] = useState(初期値);
```
- 変数A：ステートの値。この値から現在のステートの値が得られる
- 変数B：ステートの値を変更する関数（セッター関数）。この変数に引数をつけて呼び出すことでステートの値が変更される
- 初期値：ステートの初期値

### TypeScriptでの型指定
```tsx
// 型推論が効く場合（初期値から型が推論される）
const [count, setCount] = useState(0);  // number型と推論

// 明示的に型を指定する場合
const [name, setName] = useState<string>("");
const [user, setUser] = useState<User | null>(null);
const [items, setItems] = useState<string[]>([]);
```

### 更新関数の使い方
```tsx
// 直接値を設定
setCount(10);

// 関数形式（前の値を元に更新する場合はこちらを推奨）
setCount(prevCount => prevCount + 1);

// オブジェクトの更新（スプレッド構文で新しいオブジェクトを作成）
setUser(prevUser => ({ ...prevUser, name: "新しい名前" }));
```

### 注意点
- **ステートの更新は非同期**: setCountを呼んだ直後にcountを参照しても、まだ古い値の場合がある
- **オブジェクトや配列は新しい参照を作成**: 直接変更しても再レンダリングされない

```tsx
// 間違い: 直接変更
items.push("new item");  // 再レンダリングされない

// 正しい: 新しい配列を作成
setItems([...items, "new item"]);
```

## エフェクトフック (useEffect)
- 副作用（データ取得、DOM操作、タイマーなど）を扱うためのフック
- コンポーネントのレンダリング後に実行される

```tsx
useEffect(() => {
  // 副作用の処理
  console.log("レンダリング後に実行");

  // クリーンアップ関数（オプション）
  return () => {
    console.log("コンポーネントのアンマウント時、または次の実行前に呼ばれる");
  };
}, [依存配列]);
```

### 依存配列のパターン
```tsx
// 毎回のレンダリング後に実行
useEffect(() => { /* ... */ });

// 初回レンダリング後のみ実行（マウント時）
useEffect(() => { /* ... */ }, []);

// 特定の値が変わった時のみ実行
useEffect(() => { /* ... */ }, [count, name]);
```

## その他の主要なフック

### useRef
- 再レンダリングを引き起こさずに値を保持する
- DOM要素への参照を取得する
```tsx
const inputRef = useRef<HTMLInputElement>(null);
const countRef = useRef(0);  // 再レンダリングなしで値を保持
```

### useCallback
- 関数をメモ化して、不要な再生成を防ぐ
```tsx
const handleClick = useCallback(() => {
  console.log(count);
}, [count]);  // countが変わった時のみ関数を再生成
```

### useMemo
- 計算結果をメモ化して、不要な再計算を防ぐ
```tsx
const expensiveValue = useMemo(() => {
  return heavyCalculation(data);
}, [data]);  // dataが変わった時のみ再計算
```

### useContext
- コンテキストから値を取得する（プロップスのバケツリレーを回避）
```tsx
const theme = useContext(ThemeContext);
```

# フックを使わない場合(コンポーネントが関数の場合)
- Appコンポーネントの表示を更新する場合
1. Appに処理を入れる
2. Appを組み込んでいるindex.tsxに表示内容を更新する処理を入れる
## 関数
- どこからか呼び出されると実行される
- 関数内にある変数などは、関数が実行される際に作られ、実行が終わると消える
- コンポーネントの関数でも同様
- 関数である以上、コンポーネントは値を保持し続けることはできない
- → だからこそ**フック**が必要（Reactのグローバル環境に値を保存してもらう）
